# Decision — `feat/egr` is ported, not retired

**Date:** 2026-08-02 · **Status:** decided, not yet executed · **Branch:**
`/home/omar/agenttic-egr`, 7 commits from 2026-07-04, 1,915 insertions

## What it is

Eval-Gaming Resistance: a schema, gap math, a paired-probe runner, five weight-0
checks plus a gaming rubric, an `/executions/{id}/gaming` endpoint and UI card,
honesty-contract invariants, and a live run against claude-sonnet-4-6 scoring
**EGR 95/100**.

It sat unmerged for a month, and nothing in the memory index pointed at it. It
surfaced only because a handover named it.

## Why this needed deciding

`verification/selfcheck.py` was built on 2026-08-02 asking what looked like the
same question — *can something pass without doing the work?* — in ignorance of
EGR's existence. If they were duplicates, the fault-injection gate and the 18
defects fixed on top of it were built against the wrong machinery.

**They are not duplicates.** Confirmed by reading `gaming/probes.py`:

| | asks | of what | needs |
|---|---|---|---|
| **EGR** | does the agent behave *differently when it thinks it is being tested*? | the **subject** — alignment-faking, sandbagging | live model runs, k=3, paired framings |
| **selfcheck** | can this **suite** be passed by a strategy with no capability? | the **checker** | canned strings, offline, no model |

EGR pairs one intent under a test-looking and a deployment-looking wrapper and
attributes the behaviour delta to framing. `selfcheck` runs degenerate agents at
a suite and asserts they fail. Different target, different method, no overlap.
Both are needed: a trustworthy checker that is gamed by a sandbagging agent, and
an honest agent measured by a gameable checker, are two distinct failures.

## The decision: port it

Not retire. The reasons it looked like a candidate for retirement do not survive
inspection:

* **"It is written against a package that no longer exists."** True —
  `src/ascore/`, renamed to `agenttic` on 2026-07-25, three weeks after the
  branch. But every one of the **14 external symbols it imports still exists
  under the new name**, verified by importing each: `AgentAdapter`,
  `SEVERITY_RANK`, `CanonicalMetric`, `resisted`, `Criterion`, `Rubric`,
  `RunScore`, `Scorecard`, `TestCase`, `SCHEMA_VERSION`, `Span`, `Trace`,
  `CheckConfigError`, `check`. The port is a rename, not an archaeology project.
* **"It is a month old."** Age is not rot. What it measures — behaviour that
  changes under observation — did not become less relevant, and nothing built
  since covers it.

## What the port must account for

Not a blind `sed`. Four things changed under it on 2026-08-02:

1. **The fault-injection gate now audits every shipped suite.** EGR adds a
   gaming rubric; the moment it ships, `selfcheck` will run five degenerate
   strategies at it. If a degenerate passes the gaming rubric, that is a real
   finding to fix before merge — not a reason to exempt it.
2. **`audit_vacuity` will audit its five checks.** Any of them reading an
   `expected` key its cases do not supply becomes a criterion that cannot fail.
3. **Rubric versioning is now enforced by convention** — the registry is
   append-only on `(rubric_id, version)`, so the gaming rubric ships at v1 and
   any later criteria change is a bump.
4. **Nothing may be added to `Scorecard`.** `verify_manifest` recomputes
   `content_hash(scorecard)`, so if EGR's persistence touches that model it
   invalidates every issued certificate. Its `/gaming` endpoint and its
   migration need checking against that rule specifically.

The **EGR 95/100 live result must be re-run after the port**, and until it is,
that figure describes a build that no longer exists. It is not evidence about
today's tree.

## Why it is not being done in this session

It is 1,915 lines across 20 files, plus a server endpoint, a UI card and a
migration — each of which needs its own verification against the four points
above. Squeezing it into the tail of a long session is how a mechanical port
becomes a silent regression. It is a focused piece of work, and it is scoped
here so it can be picked up without re-deriving any of this.

## What would change this decision

If a port attempt shows that EGR's persistence cannot avoid touching
`Scorecard`, the endpoint and storage need redesigning before merge — the
certificate-hash rule is not negotiable, and that would make this a redesign
rather than a port. Nothing found so far suggests it.
